# 쉽게 읽기 (`content/<id>.easy.json`) 규격

`public/papers/easy.html?p=<id>` 가 이 파일을 읽어서 스크롤형 설명 페이지로 그려요.
참고 모델: "CMX를 이해하는 가장 쉬운 순서" — 번호 붙은 짧은 장, 장마다 움직이는 그림 하나, 솔직한 주의 문구.

## 독자와 수준

- **중학교 3학년 ~ 고등학교 1학년.** 함수 · 비율 · 평균 · 좌표 · 확률 정도는 알아요. 행렬 · 미분 · 로그는 몰라요.
- 전문용어는 **처음 나올 때 한 번, 그 자리에서** 쉬운 말로 풀어요. 풀지 못할 용어는 쓰지 않아요.
  - 예: "신경망이 사진을 읽어서 판단에 쓸 숫자로 바꾸는 부분을 **인코더**라고 해요."
- 수식은 쓰지 않아요. 꼭 필요하면 말로: "두 숫자를 곱해서 더해요".
- 문장은 짧게, 존댓말 "~해요" 체. 한 문단은 2~4문장.
- 비유는 좋지만, 비유가 틀리는 지점이 있으면 바로 밝혀요.
- **정확성은 양보하지 않아요.** 단순화했으면 그렇다고 말하고("실제로는 더 복잡하지만 여기선 …만 이해하면 충분해요"), 숫자는 원문 값만 써요.
- 설명용으로 지어낸 숫자 · 그림에는 반드시 "설명용 예시 · 실제 값이 아니에요" 를 붙여요 (`note` 필드).

## 이야기 순서 (권장)

1. 왜 필요한가 — 일상 장면으로 문제를 보여 줘요 (밤길 · 붐비는 교차로 · 휴대폰 사진 …).
2. 이 논문이 내놓는 "답"은 무엇인가 — 출력이 무엇인지(상자? 픽셀 이름표? 숫자?).
3. 기본 재료 — 이걸 이해하려면 꼭 알아야 할 개념 1~3개.
4. 전체 구조 한 장 — 큰 흐름(flow).
5~N. 핵심 아이디어를 하나씩 — 장 하나에 아이디어 하나.
N+1. 결과 — 원문 숫자로 무엇이 얼마나 좋아졌나 (bars).
N+2. 한계 · 아직 남은 문제.
N+3. 한 번에 이어 말하기 (recap).

장은 **9~14개**. 한 장 = 제목 1줄 + 문단 2~4개 + 그림 블록 1개(가끔 2개).

## 파일 모양

```json
{
  "id": "cmx",
  "title": "CMX",
  "kicker": "CMX · IEEE T-ITS 2023",
  "headline": "두 카메라가 서로 도우면,\n어두운 곳도 더 잘 이해할 수 있어요.",
  "lead": "RGB와 열화상을 그냥 섞는 대신, 서로의 단서를 골라 받아들이는 방법. CMX를 처음부터 설명합니다.",
  "minutes": 15,
  "sections": [
    { "title": "먼저, 두 카메라의 차이부터 볼게요.", "body": [ /* 블록들 */ ] }
  ],
  "recap": { "title": "CMX를 한 번에 이어 말하면 이렇습니다.", "text": "문단 하나 (5~8문장)", "points": ["핵심 3~5개"] },
  "words": [ { "term": "의미 분할", "easy": "사진의 픽셀마다 이름표를 붙이는 일" } ]
}
```

- `headline` 의 `\n` 은 줄바꿈. 두 줄 이내.
- `words` 는 페이지 끝 "이 페이지에 나온 말" 낱말장 (8~15개).

## 글 안의 표시

| 쓰는 법 | 보이는 모양 |
|---|---|
| `**굵게**` | 굵은 글씨 (핵심 문장 · 처음 나온 용어) |
| `{a:RGB}` | 파란 강조 (첫 번째 주인공) |
| `{b:열화상}` | 주황 강조 (두 번째 주인공) |
| `{c:정답}` | 초록 강조 (정답 · 좋은 결과) |

## 블록 (`body` 배열 안)

모든 그림 블록은 `caption`(그림 밑 한 줄)과 선택 `note`(작은 회색 글씨: 출처 · "설명용 예시")를 가질 수 있어요.
그림은 화면에 보일 때 자동으로 움직여요 (사용자가 "애니메이션 멈추기" 가능).

### `p` — 문단
```json
{ "t": "p", "text": "밤길에 사람들이 서 있어요. …" }
```

### `figure` — 원문 그림 (`public/papers/fig/<id>/` 안의 파일)
```json
{ "t": "figure", "src": "f1.jpg", "caption": "…", "note": "원문 Fig. 4" }
```
쓸 수 있는 파일은 `ls public/papers/fig/<id>/` 로 확인. 없는 파일 이름을 쓰면 안 돼요.

### `compare` — 둘(또는 셋) 나란히
```json
{ "t": "compare", "items": [
  { "label": "RGB", "tone": "a", "text": "색과 질감은 있지만, 밤에는 흐릿해요.", "icon": "eye" },
  { "label": "열화상", "tone": "b", "text": "주변과 사람의 열 차이가 드러나요.", "icon": "heat" }
], "caption": "…" }
```
`tone`: a(파랑) · b(주황) · c(초록) · d(보라) · n(회색). `icon`(선택): eye · heat · box · grid · brain · clock · chip · film · target · layers · spark · warn.

### `flow` — 단계 상자와 화살표 (차례로 불이 켜져요)
```json
{ "t": "flow", "steps": [
  { "label": "RGB 사진", "sub": "색 · 질감", "tone": "a" },
  { "label": "인코더", "sub": "단서를 숫자로" },
  { "label": "분할 지도", "sub": "픽셀마다 이름표", "tone": "c" }
], "caption": "…" }
```
3~6단계. `rows` 로 두 줄 흐름도 가능: `"rows": [[…], […]]` (`steps` 대신, 위아래 줄이 같은 칸끼리 맞춰져요).

### `grids` — 숫자 격자 (특징 맵 · 가중치 · 결과)
```json
{ "t": "grids", "items": [
  { "label": "열화상 특징", "tone": "b", "values": [[0.1,0.2,0.8],[0.1,0.8,0.8]] },
  { "label": "위치별 가중치", "values": [[0.1,0.1,0.9],[0.1,0.9,0.9]] },
  { "label": "곱한 결과", "tone": "c", "values": [[0.0,0.0,0.7],[0.0,0.7,0.7]] }
], "ops": ["×", "="], "hi": 0.5, "caption": "…", "note": "설명용 숫자 예시 · 실제 모델의 값이 아니에요." }
```
`hi` 이상인 칸이 진하게 칠해져요. 격자는 최대 6×6. `ops` 는 격자 사이 기호(개수 = 격자 수 − 1). 곱셈 예시는 **계산이 맞게**.

### `bars` — 막대 비교 (원문 숫자)
```json
{ "t": "bars", "unit": "mIoU", "items": [
  { "label": "RGB만 (SegFormer-B2)", "value": 49.2, "tone": "n" },
  { "label": "CMX (B2)", "value": 57.8, "tone": "c" }
], "max": 70, "caption": "밤 장면 점수", "note": "원문 Table IV · 높을수록 좋아요" }
```
`lower_better: true` 면 "낮을수록 좋아요"로 표시. 값은 원문 그대로, `note` 에 표 번호.

### `steps` — 번호 순서 (하나씩 켜져요)
```json
{ "t": "steps", "items": [ { "title": "평균과 최댓값 구하기", "text": "…" } ] }
```

### `analogy` — 비유 상자
```json
{ "t": "analogy", "title": "두 친구가 같이 길을 본다면", "text": "…", "limit": "비유가 틀리는 점: …" }
```

### `callout` — 주의 · 팁
```json
{ "t": "callout", "kind": "warn", "text": "가중치는 '90% 확실하다' 같은 확률이 아니에요. …" }
```
`kind`: warn(주의) · tip(알아 두면 좋아요) · key(꼭 기억).

### `scale` — 0~1 사이 값 여러 개를 눈금으로 (확률 · 점수 · 신뢰도 비교)
```json
{ "t": "scale", "items": [ { "label": "사람 상자", "value": 0.92, "tone": "c" }, { "label": "가려진 사람", "value": 0.35, "tone": "b" } ], "marks": [ { "at": 0.6, "label": "기준선 0.6" } ], "caption": "…" }
```

### `quiz` — 장 끝 확인 문제 (페이지 전체에 2~4개)
```json
{ "t": "quiz", "q": "…?", "choices": ["…", "…", "…"], "answer": 1, "why": "…" }
```

## 품질 기준 (검사 스크립트가 일부 확인해요)

- 장 9~14개, 장마다 그림 블록 ≥ 1 (p · callout · analogy 만 있는 장은 최대 2개).
- 원문 그림 `figure` ≥ 2, `bars` ≥ 1, `quiz` 2~4.
- 문단 하나 400자 이하. 영어 약어는 처음 나올 때 한국어 풀이.
- 숫자 결과는 `content/<id>.json` · `content/<id>.deep.json` 의 값과 일치.

## 학습 과학 — 페이지가 이 순서로 짜인 이유 (2026-10-03 조사)

앱 안 화면(`public/js/papers/easy.js`)이 아래를 자동으로 붙여요. 내용 파일은 `quiz` 2~4개 · `recap.points` 3~5개 · `words` 앞쪽 4개를 "가장 먼저 알아야 할 말"로 써 주면 돼요.

| 화면 | 원리 | 근거 |
|---|---|---|
| 읽기 전에 짐작하기 (첫 퀴즈 2개를 정답 없이 먼저) | 사전 시험 · 오류 생성 효과: 틀려도 먼저 답하면 나중에 더 잘 기억해요 | Richland, Kornell & Kao 2009; Pan & Carpenter 2023 리뷰 |
| 먼저 알아 둘 말 4개 | 사전 훈련 원리: 핵심 용어를 먼저 익히면 본문 이해가 깊어져요 (중앙값 d≈0.75) | Mayer, Cambridge Handbook of Multimedia Learning |
| 짧은 장 + 장마다 그림 + 굵게 · 색 강조 | 분할(d≈0.79) · 이중 부호화 · 신호(d≈0.52) | Mayer 2008/2014 |
| 본문 퀴즈 + 바로 해설 | 인출 연습: 다시 읽기보다 효과가 크고, 피드백이 있으면 더 커요 (g≈0.61, 피드백 시 ≈0.93). 중고생에서 특히 커요 | Adesope, Trevisan & Sundararajan 2017 메타분석; Dunlosky et al. 2013 '높은 효용' |
| 책 덮고 3줄 쓰기 → 정리와 맞춰 보기 → 떠올린 핵심 체크 | 자유 회상(생성) + 자기 설명 + 피드백 | Dunlosky et al. 2013; Karpicke & Blunt 2011 |
| 1 → 3 → 7일 뒤 복습 (못 맞히면 다음 날) | 간격 효과: 기억할 기간의 약 10~20% 간격이 최적 | Cepeda et al. 2008 |
| 여러 논문 문제를 섞어서 복습 | 교차 연습: 비슷한 개념을 구분하는 힘 | Dunlosky et al. 2013 ('중간 효용') |
| 일상 장면으로 시작하는 첫 장 · 제목은 질문/반전 | 호기심이 기억을 돕는다 (도파민 · 해마) | Gruber, Gelman & Ranganath 2014 |

일부러 **안 한** 것: 형광펜 · 요약 다시 읽기 위주 구성(Dunlosky 2013에서 '낮은 효용'), 학습 스타일 맞춤(근거 약함).
